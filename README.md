# Nutrition Evidence Review Pipeline

Automated, two-phase evidence-synthesis pipeline that identifies nutrition
interventions for **children under 5** and **women of reproductive age (WRA)**
in LMICs that are both **well evidence-backed** and **cost-effective**, with
realistic pathways to government-led scaling.

Pure Python 3.10+ **standard library only** — no pip dependencies (`urllib`,
`json`, `csv`, `xml.etree`).

## Two-phase design

The pipeline separates "is the evidence strong?" from "is it cost-effective?",
with a manual review checkpoint between them.

```
Phase 1 (evidence)            review            Phase 2 (cost-effectiveness)         synthesis
─────────────────────      ───────────       ──────────────────────────────      ─────────────
PubMed + OpenAlex,          you read           per shortlisted intervention,        you combine
population-targeted,    →   top_papers_   →     targeted CEA search           →     both datasets
rank → top 200 →            for_review         (PubMed + OpenAlex + optional        in-conversation
full text                   .json, write       local CEA registry)                 → FULL_INTERVENTION
                          data/shortlist.json → data/cea_by_intervention.json       _SYNTH.md
```

This split is the structural fix for the project's "CEA blind spot": cost-
effectiveness is only searched for the interventions that survive the evidence
screen, instead of being rated off a corpus that contains no relevant CEAs.

## Usage

```bash
# Phase 1 — evidence (~3–4 min, hits live NCBI/OpenAlex APIs)
python3 code/11_fetch_papers.py

# Review data/top_papers_for_review.json, then author the shortlist:
cp data/shortlist.template.json data/shortlist.json   # edit with shortlisted interventions

# Phase 2 — cost-effectiveness (scales with number of interventions)
python3 code/15_run_cea.py                    # or: python3 code/15_run_cea.py data/shortlist.json

# Produce the synthesis in-conversation following prompts/synthesis_prompt.md, then lint it:
python3 code/17_verify_synthesis.py output/FULL_INTERVENTION_SYNTH.md
```

An NCBI API key (free) speeds Phase 1 up. Put it in a gitignored `.env`:
`NCBI_API_KEY=your_key_here` — auto-loaded by `code/01_config.py`.

## Layout

```
code/                  Pipeline package — numbered by execution order (see claude.md for detail)
  11_fetch_papers.py     Phase 1 entry point (evidence)
  15_run_cea.py          Phase 2 entry point (cost-effectiveness)
  17_verify_synthesis.py Claim verifier — lints a synthesis against the corpus
data/                  All pipeline data: outputs, raw API responses, shortlist template, CEA registry
docs/                  Methodology documentation (see docs/README.md for the index)
prompts/               Stage prompts: shortlist, synthesis, extraction, and their deep-dive variants
schema/                Evidence-record schema (JSON Schema + XSD)
CARE_review/           CARE/ScaleWorks deep-dive deliverables (review + workplan)
output/                Synthesis deliverables (current); superseded renders in output/archive/
```

**Everything under `data/` is gitignored** — it is generated by the pipeline and
regenerable. The only tracked exceptions are `data/README.md` and
`data/shortlist.template.json`.
