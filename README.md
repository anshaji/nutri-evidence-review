# Nutrition Evidence Review Pipeline

Automated, two-phase evidence-synthesis pipeline that identifies nutrition
interventions for **children under 5** and **women of reproductive age (WRA)**
in LMICs that are both **well evidence-backed** and **cost-effective**, with
realistic pathways to government-led scaling.

Pure Python 3.10+ **standard library only** — no pip dependencies (`urllib`,
`json`, `csv`, `xml.etree`).

## Two-phase design

The pipeline separates "is the evidence strong?" from "is it cost-effective?",
with a manual review checkpoint between them.

```
Phase 1 (evidence)            review            Phase 2 (cost-effectiveness)         synthesis
─────────────────────      ───────────       ──────────────────────────────      ─────────────
PubMed + OpenAlex,          you read           per shortlisted intervention,        you combine
population-targeted,    →   top_papers_   →     targeted CEA search           →     both datasets
rank → top 200 →            for_review         (PubMed + OpenAlex + optional        in-conversation
full text                   .json, write       local CEA registry)                 → FULL_INTERVENTION
                            shortlist.json     → cea_by_intervention.json           _SYNTH.md
```

This split is the structural fix for the project's "CEA blind spot": cost-
effectiveness is only searched for the interventions that survive the evidence
screen, instead of being rated off a corpus that contains no relevant CEAs.

## Usage

```bash
# Phase 1 — evidence (~3–4 min, hits live NCBI/OpenAlex APIs)
python3 fetch_papers.py

# Review top_papers_for_review.json, then author the shortlist:
cp shortlist.template.json shortlist.json     # edit with shortlisted interventions

# Phase 2 — cost-effectiveness (scales with number of interventions)
python3 run_cea.py                            # or: python3 run_cea.py <shortlist.json>

# Produce the synthesis in-conversation following prompts/synthesis_prompt.md, then lint it:
python3 verify_synthesis.py output/FULL_INTERVENTION_SYNTH.md
```

An NCBI API key (free) speeds Phase 1 up. Put it in a gitignored `.env`:
`NCBI_API_KEY=your_key_here` — auto-loaded by `pipeline/config.py`.

## Layout

```
fetch_papers.py        Phase 1 entry point (evidence)
run_cea.py             Phase 2 entry point (cost-effectiveness)
verify_synthesis.py    Claim verifier — lints a synthesis against the corpus
pipeline/              The package (see claude.md for module-by-module detail)
prompts/               shortlist_prompt.md (Phase 1 → shortlist) + synthesis_prompt.md (final synthesis)
data/                  Optional local CEA registry CSV (see data/README.md)
output/                Synthesis deliverables (current + comparison runs)
shortlist.template.json   Copy → shortlist.json to drive Phase 2
```

Generated data (`papers_database.json`, `papers_ranked.csv`,
`top_papers_for_review.json`, `cea_by_intervention.json`, `shortlist.json`,
`raw_responses/`) is **gitignored** — it is regenerated by running the pipeline.
